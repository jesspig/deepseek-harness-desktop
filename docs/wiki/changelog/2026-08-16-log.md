## 2026-08-16-04 托盘退出误弹窗修复

- 用户反馈:托盘「退出」时弹出错误弹窗(dsh 进程已退出)。
- 根因:T7 重构后,托盘退出经 quitApp() 设置 main 作用域 quitting=true 并 stop() 杀子进程;子进程退出事件触发 lifecycle 内部 onChildExit,其守卫只检查 lifecycle 自身局部 quitting(尚未置位),转发到 main 的 onChildExit 后弹窗——正常退出被误判为意外退出。

## 2026-08-16-08 client 注册协议修复与链接更新修复

- 用户反馈:启动后显示 Failed to load plugins(failed to import loader entry @dsh-desktop/client: loaded without registering via __ModuleLoader__.load)。
- 根因一:浏览器端 client-modules 要求 client.js 以 window.__ModuleLoader__.load({id, factory}) 注册(官方 tsdown clientBundle 产物格式),而 tsc 直编为裸 ESM 无注册。修复:desktop-client 增加 esbuild 打包脚本 scripts/build-client.mjs(esbuild external 只支持字符串数组,external 为 react/react-jsx-runtime;banner/footer 对齐官方格式),lib/client.js 变为 loader 包装 CJS;build 脚本为 tsc && esbuild。
- 根因二:打包输出目录变更(release → build/release)后,DSH_HOME 的 profile 链接仍指向旧路径(ensurePackageLink 只在链接缺失/失效时重建),运行时加载旧产物。修复:apps/desktop/src/profile.ts 的 ensurePackageLink 用 realpath 比较链接真实目标与期望目标,不一致时重建(新增 linkTargetMatches)。
- 验证:新构建启动,profile 引导正常、URL 就绪 1.78s;client.js 返回 200 且含 __ModuleLoader__.load;无 client-modules 错误;秒开保持(窗口 37ms、前端 2.32s)。
